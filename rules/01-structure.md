# 문서 구조 골격

## 공통 골격

분야별 가이드라인 10종의 장 구성을 겹쳐 보면 네 덩어리가 같은 순서로 반복됩니다.

```
제1장  개요            ─ 왜 쓰는가, 누구에게 적용되는가
제2장  대상 분석        ─ 보호할 대상이 무엇으로 구성되는가
제3장  보안위협         ─ 실제로 무엇이 터졌고 어떻게 터질 수 있는가
제4장  보안대책         ─ 그래서 무엇을 해야 하는가
부록                   ─ 체크리스트 · 용어 · 참고문헌 · 문서이력
```

읽는 사람이 **"내 얘기인가"(1장) → "내 시스템이 이렇게 생겼나"(2장) → "이게 나한테 일어날 수 있나"(3장) → "그래서 뭘 하나"(4장)** 순으로 납득하게 만드는 구성입니다. 3장이 4장의 근거가 되므로, 3장에서 다루지 않은 위협에 대응하는 대책을 4장에 넣으면 독자가 왜 그 통제가 필요한지 알 수 없습니다.

## 제1장 — 개요

절 단위로는 다음 4개가 표준입니다. 지능형 전력망 가이드라인이 가장 전형적입니다.

```
제1절  목적
제2절  적용 범위       (또는 적용 대상)
제3절  관련 법령 및 지침
제4절  가이드라인 구성 및 활용
```

변형으로 `제1절 배경 / 제2절 용어 / 제3절 표준모델`(우주시스템)처럼 용어 정의와 대상 모델을 1장으로 끌어올리는 형태가 있습니다. 2장이 짧을 때 쓰는 방식입니다.

측정값(20종 중 등장 문서 수): 개요 9, 배경 8, 목적 7, 필요성 7, 용어 7, 관련 법령 4, 적용 범위 3, 구성 및 활용 2.

`목적`과 `필요성`은 거의 같은 비중으로 나타나고 둘 중 하나만 씁니다. `목적`은 문서가 무엇을 하려는지, `필요성`은 왜 지금 필요한지를 씁니다. 전자는 가이드라인, 후자는 가이드북·보고서 성격 문서에서 우세합니다.

## 제2장 — 대상 분석

보호 대상을 독자와 공유하는 장입니다. 세 가지 방식 중 하나를 씁니다.

| 방식 | 예 | 쓰는 때 |
|---|---|---|
| **표준모델 제시** | 우주시스템(지상국·위성망·위성체), 전력망(도메인 연계모델) | 대상이 여러 구성요소로 나뉘고 경계가 중요할 때 |
| **분류 체계 제시** | 클라우드(개념 → 분류 → 특징), AI보안(AI시스템 개요) | 대상 자체가 아직 합의되지 않은 신기술일 때 |
| **환경 변화 서술** | SW 공급망(초연결 → 분업화 → 공개SW 확대) | 위협의 뿌리가 기술보다 산업 구조일 때 |

표준모델을 제시하면 4장 대책을 모델의 구성요소별로 전개할 수 있어 가장 깔끔합니다.

## 제3장 — 보안위협

두 절로 나뉘는 것이 정석입니다.

```
제1절  침해 사례        ─ 실제 발생한 사건, 출처와 연도를 붙여서
제2절  공격 시나리오     ─ 우리 환경에서 재현했을 때의 단계별 전개
```

전력망·우주시스템·AI보안이 모두 이 형태입니다. 사례는 "일어났다"는 증거이고, 시나리오는 사례를 **우리 대상 모델 위에 올려놓은 것**입니다. 시나리오의 각 단계가 4장 대책 하나하나와 대응되도록 쓰면 문서 전체가 맞물립니다.

AI보안 가이드북은 여기에 `제3절 수명주기별 보안위협`을 더해 시간 축을 하나 더 씌웁니다. 대상의 수명주기가 길고 단계별 책임 주체가 다를 때 쓰는 확장입니다.

## 제4장 — 보안대책

가장 긴 장이고, **전개 축을 하나 골라야 합니다.** 코퍼스에는 두 축만 나타납니다.

### 축 A — 수명주기(단계)별

```
제1절  설계·개발단계 보안대책
제2절  운영·활용단계 보안대책
제3절  폐기단계 보안대책
```

우주시스템 가이드라인. 같은 통제(예: 보호구역 지정 및 관리, 용역업체 보안관리)가 여러 단계에 반복 등장하고, 단계마다 요구 수준이 달라집니다. **대상을 만드는 주체와 운영하는 주체가 다를 때** 이 축을 씁니다.

### 축 B — 구성요소·연계유형별

```
제1절  공통 보안대책            ─ 어느 구성요소에나 적용되는 것
제2절  (구성요소/연계유형)별 보안대책 ─ 1절에 더해서 적용되는 것
```

전력망(공통 → 연계유형별), 병원정보시스템(네트워크 → 시스템·애플리케이션 → 관리적), AI보안(보안대책 → 구축 유형별 중점사항), 클라우드(자체 구축 → 민간 이용).

**`공통` 절을 먼저 두고 유형별 절에서는 차이만 쓰는 것**이 이 축의 핵심 규칙입니다. 공통 절의 내용을 유형별 절에서 되풀이하면 문서가 두 배로 길어지고 둘이 어긋납니다.

### 축을 고르는 기준

- 독자가 **"나는 어느 단계에 있나"**로 자기 위치를 찾으면 축 A.
- 독자가 **"나는 어느 유형인가"**로 자기 위치를 찾으면 축 B.
- 둘 다 필요하면 축 B를 절로 쓰고 축 A를 각 절 안의 `N.` 레벨로 내립니다. 장 두 개를 각각 다른 축으로 쓰면 같은 통제가 두 곳에 흩어집니다.

## 관리적·기술적 구분

병원정보시스템은 `제2~3장 기술적 대책 → 제4장 관리적 보안대책` 순으로 관리적 통제를 뒤에 모았습니다. 관리적 통제(정책·조직, 자산 관리, 운영 관리, 물리 보안, 개인정보보호)는 기술 구성요소에 매핑되지 않으므로 축 B로 전개할 수 없고, 별도 장으로 분리하는 것이 코퍼스의 처리 방식입니다.

## 결론 장

3/20 문서만 `제5장 결론`을 둡니다(병원정보시스템 등). 통제항목 체계 문서와 법령형 지침에는 없습니다. 대책이 곧 결론이므로 **생략이 기본값**이고, 쓰는 경우에도 요약이 아니라 향후 개정 방향·후속 과제를 적습니다.

## 법령형 지침은 다른 골격을 씁니다

국가 사이버보안 기본지침은 위 골격을 쓰지 않습니다. `제N장 / 제N조` 조문 체계로 `제1조(목적) → 제2조(정의) → 제3조(적용 범위) → …` 순으로 전개하고, 위협 분석 장이 없습니다. 가이드라인이 "왜"를 설명해 설득하는 문서인 반면, 지침은 근거 법령에서 위임받은 규범을 선언하는 문서이기 때문입니다. **가이드라인을 쓰라는 요청에 조문 체계를 쓰면 장르를 잘못 고른 것입니다.**
