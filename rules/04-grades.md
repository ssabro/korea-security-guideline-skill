# 등급 매트릭스 — 기밀(C) · 민감(S) · 공개(O)

## 등급 정의

국가 망 보안체계는 정보의 중요도에 따라 세 등급으로 나누고, 등급별로 요구되는
보안통제 항목을 다르게 둡니다.

| 등급 | 표기 | 대상 |
|---|---|---|
| 기밀 | **C** (Classified) | 유출 시 국가 안보에 중대한 영향을 주는 정보를 다루는 영역 |
| 민감 | **S** (Sensitive) | 유출 시 기관 업무·개인의 권익에 상당한 영향을 주는 정보 |
| 공개 | **O** (Open) | 공개를 전제로 운영되는 영역 (대민서비스 등) |

코퍼스에서 `C 기밀 | S 민감 | O 공개` 순서로 표기하고, 등급어 단독으로 쓸 때는
`기밀`·`민감`·`공개`를 씁니다. 영문 약어 단독(`C등급`)은 표 안에서만 씁니다.

## 매트릭스 표기

통제항목 표의 마지막 세 칸이 C / S / O이고, 그 등급에서 요구되는 항목에
`●` 를 찍습니다.

```
| N2SF ID        | 소항목              | 보안통제설명 | C | S | O |
| N2SF-IV-M1     | 대면 신원 증거 검증   | …           | ● |   |   |
| N2SF-IV-1      | 관리자 승인          | …           | ● | ● |   |
| N2SF-IV-3      | 외부 신원 검증 수용   | …           | ● | ● | ● |
```

`●` 가 아닌 칸은 **비워 둡니다.** `○` 나 `-` 로 "해당 없음"을 적극 표시하지 않습니다.

## 포함 관계

측정 결과 274항목의 등급 폭 분포:

| `●` 개수 | 항목 수 | 해석 |
|---|--:|---|
| 1개 (C만) | 52 | 기밀 영역 전용 통제 |
| 2개 (C+S) | 136 | 기밀·민감 공통 |
| 3개 (C+S+O) | 85 | 전 등급 공통 |

따라서 등급별 요구 항목 수는 **C 273 ⊃ S 221 ⊃ O 85** 입니다.

**중요: 등급은 포함 관계입니다.** `S`에서 요구되는 항목은 예외 없이 `C`에서도
요구되고, `O`에서 요구되는 항목은 `S`·`C`에서도 요구됩니다. 코퍼스에 `S`나 `O`만
단독으로 `●` 인 항목은 없습니다.

이 성질은 매트릭스를 만들 때의 **검증 규칙**이 됩니다 — `●` 의 분포가
연속 구간(C / C+S / C+S+O)이 아니면 잘못 찍은 것입니다.
`S+O`(기밀에서는 불필요하고 민감·공개에서만 요구)는 논리적으로 불가능합니다.

## 항목을 어느 등급에 넣을지

코퍼스의 배분을 보면 세 가지 기준이 작동합니다.

### 1. 전 등급(C+S+O) — 기본 위생

등급과 무관하게 깨지면 시스템 자체가 위험한 통제. 85개.

- `N2SF-AC-1(4)` 비활동 시 자동 로그아웃
- `N2SF-AC-3(1)` 위협 탐지 시 노출 계정 즉시 비활성화
- `N2SF-MA-1` 관리자 계정 다중요소 인증
- `N2SF-IV-3` 동등 수준 보증의 외부 신원 검증 결과 수용

공개 영역에도 관리자는 있고 세션은 끊어야 합니다.
**관리자 권한, 세션 종료, 침해 시 즉시 조치**가 전 등급 통제의 전형입니다.

### 2. 기밀·민감(C+S) — 업무 시스템 표준

가장 큰 덩어리(136개). 내부 업무 시스템에 기대되는 통상적 보안 수준.

- `N2SF-IV-1` 계정 등록 시 관리자 승인
- `N2SF-AC-3(2)(3)` 내부·외부 사용자 모니터링
- `N2SF-DA-1` 단말 무결성 검증
- `N2SF-EI-1` 검증된 외부 자격증명 수단 활용

대민서비스에 적용하면 이용자 편의를 과하게 해치는 것들이 여기 모입니다.

### 3. 기밀 전용(C만) — 비용·불편을 감수하는 통제

52개. 운영 부담이 크거나 물리적 제약을 수반합니다.

- `N2SF-IV-M1` 대면 신원 증거 검증
- `N2SF-IM-1` 공개된 식별자의 계정 사용 금지
- `N2SF-IM-4` 상호(쌍, Pairwise) 가명 식별자 제공
- `N2SF-IM-5` 보호 저장소에서 개인·그룹·장치 속성 유지·보호
- `N2SF-AC-M1` 계정 감사 활동 자동화

**대면·가명화·전용 저장소·완전 자동화**처럼 구축 비용이 큰 통제가 기밀 전용입니다.

### 판단 질문

새 항목의 등급을 정할 때 순서대로 묻습니다.

1. 이 통제가 없으면 **공개 서비스도** 즉시 위험해지는가 → C+S+O
2. 내부 업무 시스템이면 **당연히 하고 있어야** 하는가 → C+S
3. 구축 비용·이용자 불편 때문에 **기밀 영역에서만 정당화**되는가 → C만

1번과 2번 사이에서 망설여지면 C+S로 내립니다. 전 등급 통제를 늘리면
대민서비스 운영기관이 가이드라인 전체를 무시하게 됩니다.

## 등급 선택을 독자에게 맡기는 절

본문에는 **시스템이 어느 등급인지 판정하는 절**이 따로 있어야 합니다.
클라우드 컴퓨팅 가이드라인의 `제3절 시스템 중요도 분류 기준 및 절차`가 그 예입니다.
등급 매트릭스만 주고 판정 기준을 주지 않으면 독자가 자기 등급을 모릅니다.

## 기관에 이미 있는 법정 등급 체계

**새 등급 체계를 만들기 전에 그 기관에 법정 등급 체계가 있는지 확인하세요.**
행정기관에는 ｢전자정부법｣ 제56조의3에 따른 정보시스템 등급이 있습니다. 중앙
사무관장기관이 등급산정 기준을 정하고, 기관이 분류해 제출하면 중앙사무관장
기관이 검토·변경·확정합니다.

자체 등급을 두면 체계가 둘이 되므로 관계를 밝혀야 합니다. 시험 집필에서는
세 체계가 겹쳤습니다.

| 체계 | 무엇을 정하는가 | 누가 확정하는가 |
|---|---|---|
| 법정 정보시스템 등급 | 정보시스템의 관리 수준 | 중앙사무관장기관 |
| 가이드라인의 기밀·민감·공개 | 적용할 보안통제의 범위 | 기관의 보안담당 부서 |
| 제품 보안수준(선행 자료의 L1~L4 등) | 조달할 제품이 갖출 보안 기능 | 제품 인증·시험 |

처리 원칙:

- **환산하지 않습니다.** 정하는 대상이 각각 정보시스템, 통제 범위, 제품 기능
  이므로 1:1로 바꿀 수 없습니다. 셋을 함께 기록합니다.
- **요구 수준이 어긋나면 높은 쪽을 적용합니다.**
- **법정 등급이 자체 판정보다 높으면 법정 등급을 따릅니다.** 확정 주체가 기관
  밖에 있기 때문입니다.
- 조달에 쓸 때는 등급과 제품 보안수준의 권고 조합을 표로 제시하되, 기관의
  위험 평가 결과가 더 높은 수준을 요구하면 그것이 우선임을 적습니다.

## 다른 등급 체계

코퍼스에는 다음 외부 체계도 참조로 등장합니다. 새 문서에서 등급 체계를
설계할 때 비교 대상으로 인용할 수 있습니다.

- **GSCP** (Government Security Classifications Policy, 영국) — OFFICIAL /
  SECRET / TOP SECRET 3단
- **MLS** (Multi Level Security) — 다중등급보안. 한 시스템이 여러 등급의 정보를
  동시에 처리하는 모델. CDS(Cross Domain Solution) 통제와 묶여 등장합니다.

국가 사이버보안 기본지침은 `기밀`·`민감`·`공개` 용어를 101회 쓰면서도
`C/S/O` 약어는 쓰지 않습니다. **법령형 지침에서는 한글 등급어만 씁니다.**
