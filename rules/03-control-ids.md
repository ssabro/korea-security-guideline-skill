# 통제항목 ID 체계 (N2SF)

국가 망 보안체계(N2SF, National Network Security Framework) 가이드라인과 그 보안통제 항목 해설서가 쓰는 체계입니다. 코퍼스에서 관측된 **유일한 완결형 통제항목 ID 체계**이므로, 새 가이드라인에 통제항목 번호를 붙일 때의 기준으로 씁니다.

측정값: 6 대항목 / 27 도메인 / **고유 항목 274개**.

## ID 문법

```
N2SF-<도메인 2글자>-<번호>[(<강화 번호>)]
N2SF-<도메인 2글자>-M<번호>
```

| 형태 | 예 | 뜻 |
|---|---|---|
| 기본 항목 | `N2SF-AC-1` | 도메인의 독립 요구사항 |
| 강화 항목 | `N2SF-AC-1(3)` | 기본 항목을 조건·범위를 좁혀 강화한 것 |
| M 계열 | `N2SF-AC-M1` | 해당 도메인의 **관리·감사 요구사항** |

규칙:

- **강화 항목은 모항목 없이 존재할 수 없습니다.** `N2SF-AC-1(3)`(일정 기간 미사용 계정 자동 비활성화)은 `N2SF-AC-1`(계정 관리 자동화)이 전제입니다. 모항목이 요구되지 않는 등급에서는 강화 항목도 요구되지 않습니다.
- **번호는 재사용하지 않습니다.** 항목이 삭제되면 번호는 비워 둡니다. 개정 때 번호를 당기면 기존 점검 결과·이행 증적과의 대응이 끊어집니다.
- **M 계열은 번호 공간이 분리됩니다.** `N2SF-AC-3` 과 `N2SF-AC-M3` 는 다른 항목입니다.
- 도메인 코드는 **영문 명칭의 머리글자 2글자**입니다 (Least Privilege → LP, Account Management → AC). 한글 명칭에서 따지 않습니다.

## 항목 서술 양식

해설서는 통제항목마다 아래 표 형식을 씁니다.

| 칸 | 내용 | 작성 규칙 |
|---|---|---|
| 대항목 | 권한 / 인증 / … | 6개 중 하나 |
| 중항목 | `계정관리 Account Management (AC)` | 국문 + 영문 + 코드 |
| N2SF ID | `N2SF-AC-1(3)` | 위 문법 |
| 소항목 | `계정 자동 비활성화` | **명사구.** 서술어를 붙이지 않음 |
| 보안통제설명 | `계정 사용 기간이 종료되거나 일정 기간 미사용된 계정은 자동으로 비활성화한다.` | **한 문장, `~한다`** |
| 우선 검토사항 | `● ● ●` | C / S / O 3칸, 04-grades.md 참고 |

핵심 규칙 세 가지:

1. **소항목은 명사구, 설명은 한 문장.** 소항목에 `~한다`를 붙이거나 설명을 두 문장으로 쓰면 체계가 흐트러집니다. 조건이 여럿이면 강화 항목으로 쪼갭니다.
2. **설명의 기본 종결은 `~한다`입니다.** `~해야 한다`가 아닙니다 — 05-normative-language.md 참고.
3. **설명 안에 예시를 넣을 때는 `(예: …)` 또는 `*` 로 분리합니다.** `<요구사항 문장>. * <예시 머리말> (1) <갈래>: … (2) <갈래>: …` 꼴입니다. 요구사항 문장을 먼저 끝내고 예시를 뒤에 붙입니다 — 예시를 문장 안에 끼우면 무엇이 요구사항인지 흐려집니다.

해설서 본문(부록1)은 각 도메인마다 세 절을 둡니다.

```
### N. 최소 권한 (Least Privilege, LP)
정의          ─ "…를 방지하기 위한 통제항목이다." 한 문단
보안통제 항목   ─ 위 표
구현 방법 예시   ─ 열거. "…하도록 구성한다", "…을 도입한다" 식의 구체적 수단
```

**정의 문단은 `~하기 위한 통제항목이다.` 로 끝납니다.** 27개 도메인 전부 이 틀을 씁니다. `구현 방법 예시`는 요구사항이 아니므로 ID를 붙이지 않습니다.

## 새 분야 가이드라인에 ID를 붙일 때

- **접두사를 바꿉니다.** `N2SF-` 는 국가 망 보안체계 전용입니다. 분야 약어를 쓰세요(예: 의료정보시스템이면 `HIS-AC-1`).
- **도메인 코드는 위 27개를 재사용합니다.** 접근통제·인증·암호 같은 공통 영역은 이미 코드가 정해져 있으므로, 새로 만들면 두 체계를 대조할 수 없게 됩니다. 분야 고유 영역만 새 코드를 추가하세요.
- **강화 항목과 M 계열의 의미를 그대로 유지합니다.** `(n)` 은 조건 강화, `M<n>` 은 관리·감사입니다.
- 항목 총수는 270개 내외가 한 체계의 실용적 상한입니다. 그보다 많아지면 등급으로 거르기(04-grades.md) 전에 독자가 포기합니다.
