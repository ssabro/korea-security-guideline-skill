# 배포본 조판

원고를 다 쓴 뒤 **배포할 모양으로 만드는** 단계입니다. 원고 자체를 고치는 일은
`guideline-writer`, 검사는 `guideline-lint` 가 합니다.

판면·여백·본문 크기·색은 짐작이 아니라 발행본 20종을 잰 값입니다. 근거와 수치는
[발행본 디자인 측정값](references/publication-design.md)에 있습니다. **테마를 새로
만들거나 수치를 고치기 전에 그 문서를 먼저 읽으세요.**

## 한 번에 뽑기

단계를 하나씩 부르기 전에, 보통은 이것 하나면 됩니다.

```bash
python publish.py 원고.md --theme nis
python publish.py 원고.md --theme art --theme-set motif=network
```

조판·인쇄·책 구성·목차 쪽번호·검증·쪽번호·표지 아트워크를 차례로 돌리고,
도구끼리 `--skip` 값을 주고받습니다. 100쪽 문서에 30초쯤 걸립니다.

아래는 **단계별로 따로 부를 때** 읽으세요 — 테마를 만들거나, 중간에 손을 대거나,
무엇이 어떻게 도는지 알아야 할 때입니다.

## 하는 일

```
원고.md ──render.py──▶ 1차.html ──인쇄──▶ 1차.pdf ──book.py──▶ 앞붙이 쪽수를 안다
                                                                    │
                                                                 toc.py
                                                                    ▼
원고.md ──render.py --toc──▶ 2차.html ──인쇄──▶ 2차.pdf ──book.py──▶ 책.pdf
                                                                    │
                                                              paginate.py
                                                                    ▼
                                                                배포본.pdf
```

목차 쪽번호 때문에 **두 번 인쇄합니다.** 조판하기 전에는 쪽을 알 수 없습니다.

## 책 구성

제본해서 펴낼 것을 전제로 짭니다.

차례는 이렇고, **쪽 번호는 고정이 아닙니다.**

| 차례 | 내용 |
|---|---|
| 1 | 표지 |
| 2 | 속표지 — 제목만 |
| 3 | 문서 정보 — 원고의 `## 발간 정보` |
| 4 | 목차 |
| 5 | **제1장** — 여기서부터 쪽번호 1 |
| … | 장과 부록은 저마다 새 쪽에서 시작 |
| 끝 | 판권지 — 제목과 발행 정보. 쪽번호 없음 |

**넷은 저마다 홀수 쪽에서 시작합니다.** 펼쳤을 때 오른쪽에 와야 하기 때문입니다.
앞 내용이 한 쪽을 넘치면 뒤 차례가 그만큼 밀립니다 — 문서 정보가 두 쪽이면
목차는 빈 쪽 없이 바로 이어지고, 세 쪽이면 다시 빈 쪽이 하나 들어갑니다.

그래서 **빈 쪽을 원고에 박아 넣지 않습니다.** 어느 쪽이 비어야 하는지는 인쇄해
봐야 알 수 있어서, `book.py` 가 인쇄한 뒤 필요한 만큼만 끼웁니다. 브라우저는
`break-before: recto` 를 **무시합니다**(Chrome 에서 확인).

앞붙이는 쪽번호를 매기지 않습니다. 쪽번호는 본문 첫 쪽이 1입니다.

문서이력처럼 긴 것을 앞붙이에 두고 싶으면 **원고의 `## 발간 정보` 절에 넣으세요.**
여러 쪽이 되어도 뒤가 알아서 밀립니다. 조판기에 따로 깃발을 두지 않은 것은,
무엇이 앞에 오는지는 원고가 정할 일이기 때문입니다.

## 1단계 — 조판

```bash
python render.py 원고.md --theme nis      # 테마 하나
python render.py 원고.md --all            # 다섯 테마 + 비교용 index.html
python render.py --themes                 # 테마 목록과 수치
```

`원고.md` 가 있는 폴더의 `dist/` 에 HTML 이 생깁니다.

테마는 다섯입니다. 문서 성격에 맞는 것을 고르세요.

| 테마 | 판면 | 본문 | 쓸 자리 |
|---|---|---|---|
| `nis` | 188×257mm | 10.5pt | 본체 가이드라인 **기본값** |
| `field` | 183×256mm | 11pt | 분야별 가이드라인, 보조색을 쓰는 문서 |
| `control` | 194×263mm | 8.6pt | 통제항목 해설서처럼 표가 지면 대부분인 문서 |
| `manual` | A4 | 9.5pt | 짧은 실무 안내서·지침 |
| `print` | 188×257mm | 10.5pt | 1색 인쇄·복사 전제 |

표지는 테마마다 다릅니다. 발행본에서 본 네 유형입니다.

| 테마 | 표지 | 본뜬 것 |
|---|---|---|
| `nis` `print` | 흰 바탕에 상하 굵은 괘선 | ｢국가 망 보안체계 보안 가이드라인｣ |
| `field` | 위쪽을 색으로 덮고 아래에 기관 | ｢지능형 전력망｣·｢AI 보안 가이드북｣ |
| `control` | 왼쪽 색 바 + 왼쪽 정렬 | 부속 해설서 |
| `manual` | 연한 색을 전면에 깔기 | ｢SIEM·SOAR 지침｣ |

**A4 를 기본으로 삼지 마세요.** 측정한 20종 중 A4 는 6종뿐이고 전부 짧은 지침입니다.

### 원고에서 읽어 가는 것

- 첫 `# 제목` → 표지 제목
- `## 발간 정보` 표의 `문서 종류`·`발행기관`·`작성 기준일`·`원고 버전` → 표지
- `## 목차` 아래 목록 → 목차 조판 (`제N장`·`부록`은 굵게, 절은 들여쓰기)
- `[표 N-M]`·`[그림 N-M]` → 캡션 배지
- `![](figures/*.svg)` → SVG 를 파일 안에 넣습니다
- `C`·`S`·`O` 열이 있는 표 → 통제항목 표로 조판 (등급 열 폭 고정)
- `｢법령｣` → 줄바꿈이 끼지 않게 묶습니다
- `PRS-MW-3(1)` 꼴 → 고정폭 글꼴, 줄바꿈 금지

결과 HTML 은 **외부 자원을 하나도 받아오지 않습니다.** 글꼴은 설치된 것을 차례로
쓰고 삽도는 안에 넣습니다. 망 분리 환경에서 파일 하나만 열어도 됩니다.

## 2단계 — 인쇄

브라우저에서 인쇄하면 테마의 판면 그대로 PDF 가 나옵니다. 머리말·꼬리말은 끕니다.

```bash
chrome --headless=new --disable-gpu --no-pdf-header-footer \
  --print-to-pdf="dist/배포본.pdf" --virtual-time-budget=15000 \
  "file:///절대경로/dist/nis.html"
```

경로는 **절대 경로**여야 하고 `file:///` 로 시작해야 합니다. 긴 문서는
`--virtual-time-budget` 을 넉넉히 주세요.

## 3단계 — 목차 쪽번호

1차 인쇄본에서 장·절이 시작하는 쪽을 읽어 내고, 그 값을 넣어 다시 조판합니다.

```bash
python toc.py dist/1차.pdf --source 원고.md --out dist/toc.json
python render.py 원고.md --theme nis --toc dist/toc.json
# 다시 인쇄한 뒤, 쪽이 밀리지 않았는지 확인한다
python toc.py dist/1차.pdf --source 원고.md --verify dist/2차.pdf
```

쪽번호를 **원고에 쓰지 않습니다.** 원고가 한 줄만 바뀌어도 곧바로 틀린 값이 되고,
원고를 그 인쇄본에 묶어 버리기 때문입니다. `toc.json` 은 그 인쇄본에서만 맞는
파생물이므로 버려도 됩니다.

쪽번호가 들어가면서 목차 줄 수가 바뀌지는 않으므로 보통은 쪽이 밀리지 않습니다.
그래도 `--verify` 로 확인하세요. 밀렸다면 2차 인쇄본으로 `toc.json` 을 다시 만들고
한 번 더 인쇄합니다.

항목은 원고의 `## 목차` 목록에서 가져오고 PDF 에서 **차례대로** 찾습니다.
`제1절` 처럼 장마다 되풀이되는 이름이 있어 순서를 지켜야 맞게 짚습니다. 못 찾은
항목이 있으면 원고 목차와 본문 제목이 같은지 보세요.

## 4단계 — 책 구성 맞추기

```bash
python book.py dist/2차.pdf --out dist/책.pdf
#  앞붙이 8쪽 · 본문 시작 9쪽(홀수) · 전체 101쪽 · 빈 쪽 3장 끼움
#  다음 단계에 쓸 값:  --skip 8 --start 1
```

속표지·문서 정보·목차·본문을 차례대로 짚어 짝수 쪽에서 시작하는 것이 있으면 앞에
빈 쪽을 끼웁니다. 어디를 맞춰야 하는지는 `render.py` 가 같은 폴더에 써 두는
`<테마>-구성.json` 에서 읽습니다. 알려 주는 `--skip` 값을
`toc.py` 와 `paginate.py` 에 그대로 넣으면 본문 첫 쪽이 1쪽이 됩니다.

1차 인쇄본에도 먼저 돌려서 앞붙이 쪽수를 알아낸 뒤 `toc.py` 에 넘깁니다. 2차에서
앞붙이 쪽수가 달라졌다면 목차 쪽번호를 다시 뽑아야 합니다.

## 5단계 — 쪽번호

브라우저 인쇄는 `@page` 의 머리말 영역을 만들어 주지 않습니다. 인쇄한 PDF 에
넣습니다.

```bash
python paginate.py dist/책.pdf --title "문서명" --style bottom   --skip 8 --start 1 --end 1 --head --out "dist/문서명.pdf"
```

`--end 1` 은 판권지에 번호를 넣지 않습니다. `--head` 는 아래 번호와 함께 위쪽에
문서명을 적습니다.

| 방식 | 모양 | 근거 |
|---|---|---|
| `top` (기본) | 바깥쪽 위에 `12 ｜ 문서명` | 머리말에 번호를 함께 두는 문서 6종 |
| `bottom` | 아래 바깥쪽에 번호만 | 아래 번호를 쓰는 10종 중 9종이 바깥쪽 |

표지에는 번호를 넣지 않습니다(`--skip 1`, 기본값). 한글은 설치된 글꼴을 찾아 쓰고,
없으면 내장 글꼴로 떨어집니다.

**20쪽이 넘는 문서에 쪽 표시가 없으면 배포본이 아닙니다.** 측정한 20종 중 쪽 표시가
없는 것은 6쪽짜리 지침과 훈령 둘뿐입니다.

## 테마마다 장 간지의 글자가 다르다

`book.py` 는 장 간지의 장 번호를 찾아 본문 시작을 짚습니다. 그런데 테마마다
그 글자가 다르게 나옵니다.

- 번호와 제목의 순서가 바뀝니다 — `개요 제1장`
- 자간을 벌리면 글자 사이에 빈칸이 들어갑니다 — `제 1 장`
- 세로 탭으로 눕히면 글자가 줄마다 쪼개집니다

그래서 **공백을 모두 지우고** 견주고, 쪽의 **맨 앞 44글자** 안에 있으면 장 간지로
봅니다. 본문 중간에서 다른 장을 가리키는 말은 글 속에 묻히므로 걸리지 않습니다.

판정을 "다른 장 번호가 함께 있으면 목차" 로 두었다가 틀렸습니다. 본문 쪽이 다른
장을 가리키는 것은 지극히 정상입니다 — 제1장 제1절도 제4장을 언급합니다.

앞붙이에도 `제1장` 이라는 글자가 나옵니다(발간 정보의 ※ 문장). 그래서 앞 표지들을
차례대로 짚은 **뒤부터** 본문을 찾습니다.

## 캡션과 참조를 가르는 규칙

캡션은 `[표 2-3] 제목` 꼴입니다. 본문에서 그 표를 가리킬 때는 `[표 2-3]은 …`
처럼 조사가 **바로 붙습니다.** 닫는 괄호 뒤 공백을 선택으로 두면 참조로 시작하는
문단이 캡션으로 둔갑해 **문단 첫머리가 배지에 먹힙니다.** 공백을 반드시 요구하고,
마침표로 끝나는 줄은 캡션에서 뺍니다.

예제 원고에서 이 꼴이 4군데였고, 모두 문단 앞머리를 잃고 있었습니다. 변환기는
오류를 내지 않았습니다 — 인쇄본을 봐야 보입니다.

## 색을 판면 가장자리까지 닿게 할 때

표지처럼 색이 종이 끝까지 가야 하는 쪽은 **음수 여백으로 밀어내면 안 됩니다.**
인쇄 영역 밖으로 나간 부분은 잘려 나가고, 제목 글자까지 함께 잘립니다.

이름 붙은 페이지를 써서 그 쪽만 여백을 0 으로 만듭니다.

```css
@page cover { size: 188mm 257mm; margin: 0 }
.cover { page: cover }
```

색 바탕은 `print-color-adjust: exact` 가 없으면 인쇄에서 사라집니다.

## 삽도 만들기

원고에 그림이 필요한 자리를 찾아 그려 넣습니다. 색은 조판 테마를 따르므로
문서와 삽도가 따로 놀지 않습니다. 규칙은
[삽도 — 무엇을, 언제, 어떻게](references/figure-design.md)에 있습니다.

```bash
python figplan.py 원고.md --mode review                    # 어디에 무엇이 필요한지
python figures.py 계획.json --out figures/ --theme nis      # 그린다
python figplan.py 원고.md --mode auto --plan 계획.json      # 원고에 넣는다
python figplan.py 원고-삽도.md --verify                     # 참조 무결성
```

**두 단계인 이유가 있습니다.** `review` 가 내놓는 계획에는 명세가 비어 있고,
원고를 읽고 채워야 그립니다. 도구가 혼자 노드와 연결을 지어내지 못하게 막은
것입니다 — 원고에 없는 구성요소를 그린 도식은 그럴듯해서 더 위험합니다.

기본은 `review` 입니다. `--mode targeted --target 제4장` 으로 한 장만 할 수도
있습니다. `auto` 는 원본을 덮어쓰지 않고 `<이름>-삽도.md` 를 새로 씁니다.

그릴 수 있는 꼴은 여덟입니다 — `python figures.py --types` 로 봅니다.

| | |
|---|---|
| `architecture` `flow` | 구성·흐름 |
| `process` `threat` | 절차·공격 경로 |
| `compare` `matrix` | 비교·교차표 |
| `concept` `hero` | 개념도·장 시작 |

**SVG 를 fitz 로 그려 보면 그라데이션이 검게 나옵니다.** fitz 의 SVG 지원이
좁아서이지 그림이 잘못된 것이 아닙니다. 확인은 Chrome 으로 하세요.

이미지 생성 모델은 쓰지 않습니다 — 연결된 API 가 없습니다. 사진 같은 그래픽이
필요하면 계획에 적어 두고 발행기관이 별도로 만듭니다.

## 반드시 눈으로 보세요

조판은 글로 검사되지 않습니다. 만들고 끝내지 말고 **렌더링해서 보세요.** 이 스킬을
만드는 동안 눈으로만 잡힌 결함이 여섯이었습니다 — 표지가 없었고, 목차가 맨 불릿이었고,
통제표 첫 열이 두 줄로 깨졌고, 90쪽 문서에 쪽번호가 없었고, 표지 다섯이 서로 구분되지
않았고, 음수 여백 때문에 표지 제목이 잘렸습니다. **어느 것도 변환기가 오류를 내지
않았습니다.** 여기에 캡션으로 둔갑한 문단 4건이 더해집니다.

```bash
# PDF 몇 쪽을 그림으로 떠서 본다
python - <<'PY'
import fitz
from PIL import Image
d = fitz.open('dist/배포본-최종.pdf')
for i in (0, 1, 12, 40):
    p = d[i].get_pixmap(dpi=100)
    Image.frombytes('RGB', (p.width, p.height), p.samples).save('p%d.png' % i)
PY
```

표지, 목차, 장이 바뀌는 쪽, 표가 긴 쪽, 삽도가 있는 쪽을 봅니다.

기계로 볼 것은 따로 있습니다.

```bash
grep -o 'https\?://[^"]*' dist/nis.html | grep -v w3.org   # 외부 자원 — 하나도 없어야 한다
grep -c '<table' dist/nis.html                              # 표 수가 원고와 맞는가
grep -c '^\s*|' dist/nis.html                               # 변환 못 한 표 행 — 0 이어야 한다
```

## 도구

| 파일 | 하는 일 |
|---|---|
| `publish.py` | **원고 → 배포본 PDF. 아래 도구를 차례로 돌린다** |
| `render.py` | 원고 → 배포용 HTML. 테마 등록·목차 쪽번호 주입 |
| `book.py` | 인쇄본을 책 구성에 맞춘다. 빈 쪽을 끼우고 앞붙이 쪽수를 알려 준다 |
| `toc.py` | 인쇄본에서 장·절 시작 쪽을 읽어 목차 쪽번호를 만든다 |
| `paginate.py` | 쪽번호와 머리말을 넣는다 |
| `figplan.py` | 삽도가 필요한 자리를 찾고, 그려서 원고에 넣는다 |
| `figures.py` | 명세를 받아 삽도를 SVG 로 그린다 |
| `coverart.py` | 인쇄한 PDF 의 표지에 아트워크를 깔아 준다 |
| `themegen.py` | 기존 발행물을 재서 테마 뼈대를 만든다 |

## 기관의 기존 발행물에 맞추기

기관이 이미 펴낸 책을 건네면 거기서 재서 테마 뼈대를 만듭니다.

```bash
python themegen.py 기관_작년_가이드라인.pdf --key ourorg --label "우리 기관 표준"
#   판면 185x254mm · 본문 10.2pt · 여백 24/23/18/15
#   제목색 #1b3a6b(9쪽) · 채움색 #d7eaf9(13쪽) …
#   → themes/ourorg.py
```

**주조색은 제목 글자 색에서 찾습니다.** 도형 채움만 보면 한두 쪽에 크게 깔린
포인트 색이 뽑힙니다 — 실제로 ｢국가 망 보안체계｣ 에서 빨강이 남색을 이겼습니다.
제목을 먹색으로 조판한 문서에서는 채움색으로 떨어집니다. 후보를 모두 테마 파일
주석에 적어 두니 **한 줄 바꿔 끼우면 됩니다.**

**뼈대일 뿐입니다.** 측정은 판면과 색을 짚어 주지만 배지 모양이나 표지 구성까지
알려 주지는 못합니다. 열어서 손보세요.

값 몇 개만 바꿔 보고 싶으면 파일을 만들지 않아도 됩니다.

```bash
python render.py 원고.md --theme nis --set accent=#1b3a6b --set body=10.2
python render.py 원고.md --theme art --set motif=network --set page=190,260
```

## 표지 아트워크

실제 발행본의 표지는 글자만 있지 않습니다. `art` 테마는 기하 구성을 전면에
깝니다 — `crystal`(모난 다각형) · `network`(점과 선) · `wave`(동심원) ·
`grid`(아이소메트릭). 색은 테마를 따릅니다.

```bash
python render.py 원고.md --theme art --set motif=network
# 인쇄한 뒤 — 표지와 장 간지에 함께 깐다
python coverart.py 책.pdf --theme art --title "문서명" --chapters --out 최종.pdf
```

`--chapters` 는 **전면 장 간지**에도 깝니다. 장마다 무늬를 돌려 가며 쓰고,
장 번호를 씨앗으로 삼아 같은 장은 늘 같은 그림이 나옵니다.

간지를 찾는 규칙은 `book.py` 와 같되 하나를 더 봅니다 — **글자가 아주 적은
쪽**만 고릅니다. 목차 첫 쪽도 "제1장 개요 1 제1절 …" 으로 시작하지만 글자가
수백 자입니다. 전면 간지를 쓰지 않는 테마에서는 아무것도 찾지 못하며, 그때는
간지에 그림을 깔 자리가 없다는 뜻입니다.

간지에는 쪽번호와 머리말을 넣지 않습니다.

```bash
python paginate.py 책.pdf --style bottom --skip 8 --start 1 --end 1 --head   --sparse 70 --title "문서명"
```

`--sparse 70` 은 글자가 70자도 안 되는 쪽(전면 간지·빈 쪽)에 쪽 장식을 넣지
않습니다. **번호는 그대로 셉니다** — 찍지 않을 뿐입니다. 전면 색면에 회색
머리말이 찍히면 얼룩처럼 보입니다.

**왜 인쇄 뒤에 깔까요.** CSS 로는 종이 끝까지 채우지 못했습니다. `@page cover
{margin:0}` 과 `height:257mm` 를 줘도 인쇄에서 상자가 232.8mm 에서 잘립니다 —
쪽 조각화가 걸려 쪽 내용 영역에 맞춰지고, 아래 24mm 가 희게 남습니다. 쪽번호와
같은 방식으로 **인쇄한 뒤에 글자 아래에 깝니다**(`overlay=False`).

그래서 인쇄용 CSS 에서는 쪽 바탕을 투명하게 둡니다. 흰색이 덮여 있으면 밑에 깐
그림이 가려집니다.

### 기관 로고

원고 폴더의 `logos/` 에 기관이 넣은 파일(SVG·PNG·JPG)을 표지 아래에 올립니다.
폴더가 없으면 아무것도 그리지 않습니다.

**로고를 지어내지 않습니다.** 정부기관 로고를 만들어 붙이는 것은 위조입니다.
기관이 준 파일만 씁니다.

## 테마를 고치거나 더할 때

`themes/` 에 파일 하나가 테마 하나입니다. 쓸 수 있는 값과 조판기가 내는 class
이름은 [테마 만들기](themes/README.md)에 있습니다.

수치는 측정값에서 가져오고, 가져올 값이 없으면 **왜 그 값인지 주석으로 적으세요.**
측정에서 온 값인지 판단으로 정한 값인지 구분이 안 되면 다음 사람이 근거 없이
따라 합니다.

색은 넷을 넘기지 마세요 — 짙은 남색, 중간 파랑, 연한 하늘, 보조색 하나.

## 하지 않는 것

- **HWP·HWPX 로 내보내기** — 기관이 한글 파일을 요구하면 `hwp` 스킬을 쓰세요.
  이 스킬은 HTML 과 PDF 만 만듭니다.
- **원고 고치기** — 변환기는 원고를 읽기만 합니다. 내용이 잘못됐으면 원고를
  고치고 다시 돌리세요.
- **표지 그래픽** — 제목·발행기관·연월만 조판합니다. 사진이나 일러스트, 기관
  로고는 발행기관이 넣습니다.
