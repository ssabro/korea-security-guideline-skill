# 법령 인용 검증 대장 양식

`SKILL.md` 5단계에서 쓰는 양식입니다. 가이드라인 원고와 **같은 폴더에 따로 두고** 발행 전에 법무 검토로 넘깁니다. 발행본에는 포함하지 않습니다.

왜 따로 두는가 — 조문 번호는 짐작으로 쓸 수 없고, 무엇을 어떤 출처로 확인했는지 남기지 않으면 검토 단계에서 처음부터 다시 확인하게 됩니다. **발행된 정부 간행물의 인용도 틀립니다**(`rules/06-notation.md`).

---

## 양식

```markdown
# 출처 검증 대장

대상: `<원고 파일>` (v0.1 → v?.?)
검증 기간: <시작> ~ <종료>
상태: <진행 중 | 종료>

## 1. 검증 완료 — 원고에 반영

| 대상 | 검증 결과 | 1차 출처 | 반영 위치 |
|---|---|---|---|

## 2. 원고에서 고친 오류

| 무엇이 틀렸나 | 왜 틀렸나 | 어떻게 고쳤나 |
|---|---|---|

## 3. 남은 확인 필요 — 법무·기술 검토에 넘길 것

| 순위 | 대상 | 확인할 것 | 이유 |
|---|---|---|---|

## 4. 도구 제약으로 확인하지 못한 것
```

2절을 비워 두지 마세요. **고친 오류가 하나도 없는 검증은 검증을 하지 않은 것입니다.**

---

## 무엇을 확인 대상에 넣는가

| 종류 | 확인할 것 |
|---|---|
| 본법 조문 | 조 번호, 항·호·목, 조문 제목, 시행일, 법률번호 |
| 시행령·시행규칙 | 본법이 위임한 사항 — **주기·수단·범위·요건이 여기 있습니다** |
| 벌칙·과태료 | 의무별 제재 수준. 통제의 우선순위를 정하는 근거가 됩니다 |
| 훈령·고시 | 정확한 명칭, 현행 개정일, **종전 명칭** |
| 선행 발행물 | 정확한 제목, 발행기관(공동 발행 여부), 발간 시점, 발간등록번호 |
| 외국 표준 | 공식 영문 제목, 판, 발행 시점, 개정 동향 |

## 조문을 어디서 확인하는가

**국가법령정보센터(law.go.kr)의 일반 페이지는 조문 본문을 스크립트로 렌더링해 자동 수집 도구로 읽히지 않습니다.** 법령 전체의 시행일과 법률번호는 보이지만 조문 본문이 비어 옵니다. 사람이 브라우저로 보거나, 아래 API 를 쓰십시오.

**법제처 국가법령정보 공동활용**(`open.law.go.kr`)이 OPEN API 를 제공합니다. `OPEN API 활용가이드` 에 다음이 들어 있어 이 검증에 그대로 맞습니다.

| 필요한 것 | 공동활용에서 찾을 곳 |
|---|---|
| 조문 본문 | 법령 **조항호목 조회** |
| 시행일·공포일 기준 현행 법령 | 시행일 법령, 공포일 법령 |
| 개정 전후 대조 | 신구법 비교, 3단 비교, 변경 이력 |
| 훈령·고시 | **행정규칙** |
| 위원회 결정·안내 | 위원회 결정문(개인정보보호위원회 등) |
| 위임 관계 추적 | 위임법령, 체계도 |

사용에는 신청이 필요합니다 — 같은 사이트의 `OPEN API 신청` 과 `OPEN API 활용방법` 페이지를 보십시오.

### 조회를 도와주는 외부 스킬·도구

조회 자체를 자동화하는 공개 프로젝트가 있습니다. **에이전트용 스킬 형태로 제공되는 것**으로는 [Legalize-KR Agent Skills](https://github.com/legalize-kr/agent-skills) 가 가장 가깝습니다(Apache-2.0 · MIT 이중 라이선스).

| 항목 | 확인한 내용 |
|---|---|
| 구성 | `skills/legalize-kr/SKILL.md` 와 `references/`, 보조 Python 스크립트. 실행 바이너리는 배포하지 않음 |
| 범위 | 법령·판례·행정규칙·자치법규. 자료는 각각 별도 저장소에 Markdown 으로 보관 |
| 인증키 | **필수 아님.** 토큰 없이 동작하고, 반복 검색을 하면 GitHub API 한도에 걸립니다 |
| 사용 경로 | 플러그인 설치, `npx skills add`, MCP 서버, **문서를 프롬프트에 넣기** 중 선택 |

그 밖에 법제처 OPEN API 를 감싼 MCP 서버도 여럿 공개되어 있습니다.

**다만 이 저장소는 어느 것도 복사해 넣지 않습니다.** 이유는 하나입니다 — **법령은 시간에 민감합니다.** 이 저장소가 복사해 둔 `korean-skills` 는 문체 규칙이라 몇 달 지나도 틀리지 않지만, 법령 자료의 사본은 개정이 반영되지 않으면 **틀린 조문을 자신 있게 인용하게 만듭니다.** 사본을 저장소에 넣으면 그 최신성 책임을 이 저장소가 지게 됩니다. 쓰실 분이 직접 최신본을 설치하는 편이 맞습니다.

도구를 쓰실 때 지킬 것이 둘입니다.

- **미러는 1차 출처가 아닙니다.** 외부 저장소의 Markdown 사본으로 찾은 조문은 발행 전에 법제처 원문과 대조하십시오. 특히 최근 개정된 법령이 그렇습니다.
- **검증 대장은 사람이 채우십시오.** 조문을 가져오는 것과, 그 조문이 원고의 인용과 맞는지 판단하는 것은 다른 일입니다.

## 확인 중에 자주 드러나는 것

시험 집필에서 실제로 나온 순서입니다. 조문을 대조할 때마다 하나씩 나왔습니다.

- **인용 오류** — 다른 간행물의 인용 형식을 따랐다가 조 번호가 틀린 경우, 법령의 용어를 비슷한 말로 잘못 적은 경우.
- **가정 역전** — 하위 법령이 더 엄격할 것이라 가정했는데 원고가 더 엄격한 경우. 이때는 "하위 법령이 우선한다"가 아니라 "원고를 따르면 하위 법령도 충족된다"로 써야 합니다. **주기와 기한을 구분**하세요 — 주기를 지켜도 기한은 따로 지켜야 합니다.
- **통제 간 충돌** — 금지 통제와 예외가 열린 통제가 같은 대상을 가리킬 때.
- **누락 체계** — 기관에 이미 있는 법정 등급·인증·보고 체계를 모르고 쓴 경우.
- **누락 통제** — 법문이 요구하는데 원고에 대응 통제가 없는 경우.
- **서술 공백** — 조건이 붙은 지위를 조건 없이 적은 경우.

## 확인 결과를 원고에 반영하는 방식

- 조문별 의무를 **표로 정리**합니다. 열은 `조문 | 의무 | 로봇 운용에서의 의미` 처럼 두어, 법문과 그 법문이 이 문서에서 뜻하는 바를 분리합니다.
- **법문을 그대로 옮기지 말고 문서의 어미로 고쳐 씁니다.** 법령은 `~하여야 한다`를 쓰므로 그대로 옮기면 문체가 섞입니다(`govdoc-style`).
- 조문을 특정하지 못한 법령은 **표에서 빼는 편이 낫습니다.** 법령명만 적힌 행은 검토 단계에서 반드시 지적받습니다.
- 2차 출처로만 확인한 항목은 원고에 **그 사실을 ※ 로 적어 둡니다.**

## 재확인이 필요해지는 경우

검증을 종료한 뒤에도 다음 셋은 추적합니다. 대장 3절에 적어 둡니다.

- 인용한 법령이 개정될 때
- 인용한 외국 표준의 새 판이 나올 때
- 선행 발행물이 개정될 때
