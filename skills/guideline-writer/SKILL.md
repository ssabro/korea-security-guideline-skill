# 사이버보안 가이드라인 집필

한국 정부·공공기관이 발행한 사이버보안 가이드라인 20종(1,883쪽 / 1,450,128자)을
측정해 증류한 규칙에 따라 같은 형식·문체의 문서를 작성합니다.

규칙은 [`rules/`](../../rules/) 에 있습니다. 이 스킬이 하는 일은 그 규칙을
집필 순서대로 적용하는 것입니다. 본문에 나오는 수치는 그 20종을 측정한 값입니다.

## 먼저 확인할 것

작성에 들어가기 전에 네 가지가 정해져야 합니다. 요청에 없으면 물어보세요.
추측해서 쓰면 나중에 장 구성을 통째로 다시 짜게 됩니다.

| 항목 | 선택지 | 결정이 바꾸는 것 |
|---|---|---|
| **장르** | 분야별 가이드라인 / 통제항목 체계 / 법령형 지침 / 실무 안내서 | 골격, 번호 체계, 종결어미 전부 |
| **대상** | 보호할 시스템·기술·분야 | 2장의 서술 방식 |
| **전개 축** | 수명주기별 / 구성요소·연계유형별 | 4장 절 구성 |
| **통제항목 체계** | 쓴다 / 안 쓴다 | ID 부여, 등급 매트릭스 필요 여부 |

장르가 모호하면 `AskUserQuestion` 으로 묻되, 다음 신호로 먼저 추정하세요.

- "가이드라인"·"가이드북"을 쓰고 특정 분야(의료·전력·우주·AI)가 있으면 → **분야별 가이드라인**
- 점검·이행 확인이 목적이고 항목에 번호를 붙여야 하면 → **통제항목 체계**
- 근거 법령에서 위임받은 규범을 선언하는 문서이면 → **법령형 지침**
- 짧고 실무자가 바로 따라 하는 문서이면 → **실무 안내서**

장르별 차이는 [`rules/README.md`](../../rules/README.md) 의 "측정 대상 20종" 표에
있습니다. **장르를 고른 뒤에는 그 장르의 규칙만 적용하세요.** 섞으면 즉시 어긋나 보입니다.

## 작업 흐름

### 0단계 — 선행 자료 조사

**같은 분야의 발행물이 이미 있는지 먼저 확인하세요.** 모르고 쓰면 중복
발행이 되고, 알고도 밝히지 않으면 기관이 두 문서 중 무엇을 따를지 판단할 수
없습니다.

- 발행 기관의 자료실과 분야 소관 기관의 공개 자료를 봅니다.
- 선행 자료를 찾으면 **적용 대상과 적용 범위를 먼저 읽으세요.** 제조사용인지
  운영자용인지, 제품만 다루는지 운영 환경까지 다루는지에 따라 겹치는 정도가
  달라집니다.
- 겹치면 **역할 분담 절을 1장에 둡니다.** 어느 영역을 어느 자료에서 보는지
  표로 적고, 같은 통제를 두 자료가 다루면 어느 쪽이 우선인지 밝힙니다.
- **겹치는 통제의 구현 방법을 다시 쓰지 마세요.** 선행 자료를 가리키고,
  대응 관계를 부록의 대응표로 제공합니다. 고유 통제에만 구현 방법 예시를 둡니다.

선행 자료가 보안수준 체계를 쓰고 있으면 자기 등급 체계와의 관계를 밝힙니다
(`rules/04-grades.md`).

### 1단계 — 골격 확정

[`rules/01-structure.md`](../../rules/01-structure.md) 를 읽고 장·절 목록을 먼저
확정합니다. 본문을 쓰기 전에 목차가 끝나 있어야 합니다.

분야별 가이드라인의 기본 골격:

```
제1장  개요
  제1절  목적                      (또는 배경·필요성 중 하나)
  제2절  적용 범위
  제3절  관련 법령 및 지침
  제4절  가이드라인 구성 및 활용
제2장  <대상> 개요               ← 표준모델 / 분류 체계 / 환경 변화 중 하나
제3장  <대상> 보안위협
  제1절  침해 사례
  제2절  공격 시나리오
제4장  <대상> 보안대책
  제1절  공통 보안대책            ← 축 B를 고른 경우
  제2절  <유형>별 보안대책
부록                            ← 체크리스트 / 용어 / 약어 / 참고문헌 / 문서이력
```

확정할 때 점검할 것:

- **3장의 위협과 4장의 대책이 1:1로 맞물리는가.** 3장에 없는 위협에 대응하는 대책을
  4장에 넣으면 독자는 그 통제가 왜 필요한지 알 수 없습니다. 목차 단계에서
  위협 ↔ 대책 대응표를 만들어 두세요.
- **전개 축을 하나만 썼는가.** 장 두 개를 각각 다른 축으로 쓰면 같은 통제가 흩어집니다.
  두 축이 다 필요하면 축 B를 절로, 축 A를 절 안의 `N.` 레벨로 내립니다.
- **공통 절을 먼저 두었는가.** 축 B에서는 공통 절에 쓴 내용을 유형별 절에서
  되풀이하지 않습니다.

### 2단계 — 통제항목 체계 설계 (쓰는 경우)

[`rules/03-control-ids.md`](../../rules/03-control-ids.md) 와
[`rules/04-grades.md`](../../rules/04-grades.md) 를 읽습니다.

ID 문법:

```
<분야약어>-<도메인 2글자>-<번호>[(<강화 번호>)]
<분야약어>-<도메인 2글자>-M<번호>
```

- 접두사는 분야 약어로 바꿉니다. `N2SF-` 는 국가 망 보안체계 전용입니다.
- **도메인 코드 27개는 재사용합니다** — 접근통제·인증·암호 같은 공통 영역은 이미
  코드가 정해져 있습니다. 새로 만들면 두 체계를 대조할 수 없게 됩니다.
  분야 고유 영역만 코드를 추가하세요.
- `(n)` 은 조건 강화, `M<n>` 은 관리·감사 요구사항. 의미를 바꾸지 마세요.
- 강화 항목은 모항목이 없으면 존재할 수 없고, 모항목이 요구되지 않는 등급에서는
  강화 항목도 요구되지 않습니다.

항목 서술 양식:

| 칸 | 규칙 |
|---|---|
| 소항목 | **명사구.** 서술어를 붙이지 않음 |
| 보안통제설명 | **한 문장, `~한다`** 로 끝남 |
| 등급 | C / S / O 3칸에 `●`, 해당 없으면 빈칸 |

조건이 여럿이면 한 문장에 밀어 넣지 말고 강화 항목으로 쪼갭니다.

**새 근거를 찾을 때마다 통제를 늘리지 마세요.** 법령 조문이나 선행 자료를
확인하다 보면 통제를 추가할 구실이 계속 생깁니다. 기존 통제가 그 위험을 이미
다루고 있으면 **통제를 늘리는 대신 설명·구현 예시·근거를 보강하는 쪽**이 낫습니다.
항목이 늘어날수록 기관이 문서를 덮을 확률이 올라갑니다.

통제를 새로 만들어야 하는 경우는 셋입니다.

- 기존 통제가 다루지 않는 **새 위험**이 확인될 때
- 두 통제가 서로 **충돌**해 중재가 필요할 때(아래 예 참고)
- **법정 의무**가 있는데 대응 통제가 없을 때

등급은 포함 관계(C ⊃ S ⊃ O)입니다. 항목마다 순서대로 물으세요.

1. 이 통제가 없으면 **공개 서비스도** 즉시 위험해지는가 → C+S+O
2. 내부 업무 시스템이면 **당연히 하고 있어야** 하는가 → C+S
3. 구축 비용·이용자 불편 때문에 **기밀 영역에서만 정당화**되는가 → C만

1번과 2번 사이에서 망설여지면 C+S로 내립니다. 전 등급 통제를 늘리면
대민서비스 운영기관이 가이드라인 전체를 무시합니다.

**등급 매트릭스를 쓰면 등급 판정 절을 본문에 두어야 합니다.** 매트릭스만 주고
자기 시스템이 어느 등급인지 판정할 기준을 주지 않으면 독자가 쓸 수 없습니다.

**통제끼리 충돌하는지 점검하세요.** 각각은 옳은데 함께 두면 서로를 막는 쌍이
생깁니다. 시험 집필에서 나온 예입니다.

```
PP-5  촬영 금지 장소에서는 영상 수집을 중단한다
PP-6  수집 목적과 다른 목적의 카메라 조작을 금지한다
```

수집 중단을 풀 수 없게 잠그면 법이 허용한 인명 구조 상황에서 촬영을 못 하고,
쉽게 풀리게 하면 목적 외 조작 금지가 무너집니다. 해법은 둘 중 하나를 버리는
것이 아니라 **해제 권한·절차를 정하고 해제를 기록하는 세 번째 통제**였습니다.

금지 통제와 예외가 열린 통제가 같은 대상을 가리키면 이 점검이 필요합니다.

### 3단계 — 본문 작성

**원고는 한 문단을 한 줄로 씁니다.** Markdown 파일 자체가 작성의 원본이므로,
폭에 맞춰 줄을 감지 않습니다. 이유가 둘입니다.

- 문장을 고칠 때마다 문단을 다시 감아야 합니다. 한 단어를 넣으면 아래 줄이
  전부 밀립니다.
- **`guideline-lint` 의 검사는 줄 단위입니다.** 용어 혼용, 주기 누락, 위치 표현
  같은 검사가 "같은 줄"을 봅니다. 문단을 감아 두면 `정기적으로` 와
  `반기 1회 이상` 이 다른 줄에 떨어져, 주기를 적었는데도 지적을 받습니다.
  문단을 한 줄로 쓰면 "같은 줄"이 곧 "같은 문단"이 됩니다.

이미 감긴 원고는 [`unwrap.py`](unwrap.py) 로 펼칩니다. 표 행과 코드 블록은
건드리지 않고, 공백 외의 글자가 바뀌지 않았는지 검증한 뒤 덮어씁니다.

```bash
python skills/guideline-writer/unwrap.py 원고.md --check   # 바뀔 줄 수만 본다
python skills/guideline-writer/unwrap.py 원고.md
```


[`rules/05-normative-language.md`](../../rules/05-normative-language.md),
[`rules/06-notation.md`](../../rules/06-notation.md),
[`rules/07-terminology.md`](../../rules/07-terminology.md) 를 적용합니다.

가장 틀리기 쉬운 규칙 네 가지:

**통제항목의 기본 종결어미는 `~한다` 입니다.** `~해야 한다`가 아닙니다.
코퍼스에서 서술 3,073회 대 의무 1,332회이고, 통제항목 해설서 단독으로는 883 대 25입니다.
이 장르에서 `~한다`는 그 자체로 요구사항이므로 `~해야 한다`를 덧붙이면 중복이고,
전부 그렇게 쓰면 모든 항목이 같은 세기가 되어 등급 구분이 사라집니다.
`~해야 한다`는 본문에서 특정 통제를 강조할 때 아껴 씁니다.

**의무 표현은 문서 안에서 하나로 통일합니다.** 가이드라인은 `~해야 한다`,
법령형 지침은 `~하여야 한다`. `~하여야 한다`는 법령 인용문 안에서만 그대로 둡니다.

**주기는 하한을 명시합니다.** 코퍼스는 `정기적으로`를 102회 쓰지만 구체 주기가
거의 붙지 않습니다. 이 지점은 코퍼스를 따르지 마세요 — 주기가 없으면 점검할 수
없는 통제가 됩니다. 하한을 정할 근거가 없다면 그 통제는 아직 요구사항이 아니라
권고입니다.

**깊이를 쓰지 않습니다.** 제목은 `N.` 레벨(3단)에서 멈추는 것이 기본이고,
불릿은 2단까지입니다. 더 깊어지려면 제목 레벨로 올리세요.

### 4단계 — 부록과 파생 산출물

- **체크리스트는 본문 대책과 1:1로 대응**해야 합니다. 본문 대책을 자가진단
  문항으로 뒤집은 것이고, 본문에 없는 문항이 들어가면 안 됩니다.
- **부록은 본문에서 생성하세요.** 통제항목을 하나 더하면 체크리스트, 대응표,
  본문의 등급별 요구 항목 수가 함께 밀립니다. 손으로 맞추면 반드시 어긋나므로,
  본문 표를 읽어 부록을 다시 만드는 방식이 안전합니다. `guideline-lint` 의
  `CHECKLIST-EXTRA`·`CHECKLIST-MISS`·`GRADE-COUNT` 가 어긋남을 잡습니다.
- 약어가 10개를 넘으면 약어표를 둡니다.
- 개정 문서는 문서이력을 둡니다.

본문이 길어지면 **파생 산출물**을 함께 만듭니다. 본문을 줄이는 것보다 독자별로
나누는 편이 낫습니다.

| 산출물 | 장르 | 주의할 점 |
|---|---|---|
| 운영 담당자용 요약 | **실무 안내서(경어체)** | 요약이 아니라 재구성입니다. 주기별 할 일, 금지 사항, 사고 시 순서로 묶으면 본문보다 훨씬 짧아집니다 |
| 점검 체크리스트 스프레드시트 | — | 등급·구분·대응 관계로 걸러 쓰도록 필터를 둡니다 |

**삽도는 `guideline-design` 이 만듭니다.** `figplan.py --mode review` 가 그림이
필요한 자리를 찾아 주고, 명세를 채우면 `figures.py` 가 그립니다. 색은 조판
테마를 따르고 캡션은 `[그림 N-M]` 규칙이라 `guideline-lint` 검사를 그대로
통과합니다. **원고에 없는 구성요소나 연결을 그린 도식은 그럴듯해서 더
위험하므로**, 도구가 혼자 그리지 못하게 명세를 사람이 채우는 구조입니다.

**요약본은 장르가 바뀌므로 문체를 통째로 갈아야 합니다.** 본문은 비경어체
`~한다`, 요약본은 경어체 `~합니다`이고 번호 체계도 `제N장/제N절`에서 `N./N.N`로
바뀝니다. 본문 문장을 그대로 옮기면 즉시 어긋납니다. 검사할 때도
`--genre manual` 로 따로 돌리세요.

### 5단계 — 법령 인용 검증

**발행하려면 인용한 조문을 모두 원문과 대조해야 합니다.** 조문 번호를 짐작하거나
다른 간행물의 인용을 그대로 옮기면 틀립니다(`rules/06-notation.md`).

검증 대장을 따로 만드세요. 양식과 작성 요령은
[`references/verification-log.md`](references/verification-log.md) 에 있습니다.
**조문 본문은 국가법령정보센터의 일반 페이지에서 자동으로 읽히지 않습니다** —
법제처 국가법령정보 공동활용(`open.law.go.kr`)의 조항호목 조회 API 를 쓰거나
사람이 브라우저로 확인합니다. 같은 참조 문서에 적어 두었습니다.

- **본법만 보지 말고 시행령·시행규칙까지 내려가세요.** 주기·수단·범위 같은
  실무 수치가 하위 법령에 있습니다. 시험 집필에서는 취약점 분석·평가 주기,
  촬영 사실 표시 수단, 실외이동로봇의 범위가 모두 하위 법령에 있었습니다.
- **벌칙·과태료 조항을 함께 확인하세요.** 제재 수준이 의무별로 다르면
  통제의 우선순위를 정하는 근거가 됩니다.
- **조문이 다른 법을 가리키면 끝까지 따라가세요.** 두 법이 서로를 가리키며
  닫히는 구조에서 조건이 드러나는 경우가 있습니다.
- 확인하지 못한 항목은 **빈칸으로 남기지 말고 미확인으로 적습니다.** 조문을
  특정하지 못하면 표에서 빼는 편이 낫습니다 — 법령명만 적힌 행은 검토 단계에서
  반드시 지적받습니다.

### 6단계 — 검사

작성이 끝나면 `guideline-lint` 스킬로 기계적으로 검사할 수 있는 항목을
먼저 걸러내세요. 종결어미 혼용, 경어체 혼입, 꺾쇠·캡션 혼용, 통제항목 ID 문법,
등급 매트릭스 연속성, 주기 없는 통제, 용어 혼용을 잡습니다.

문체를 더 다듬어야 하면 `govdoc-style`(공문서 문체 일관성)과
`grammar-checker`(맞춤법·띄어쓰기)를 씁니다. `grammar-checker` 는
[korean-skills](https://github.com/DaleSeo/korean-skills)(Dale Seo, MIT)의
스킬을 그대로 가져온 것이고, 이 저장소의 집필 흐름은 그 스킬에 의존합니다.

## 근거를 밝힐 때

이 스킬은 규칙을 적용하지, 원본 문서의 문장을 옮기지 않습니다.

- **발행 문서의 문장을 그대로 베끼지 마세요.** 통제항목 설명문을 복제하면
  출처 문서의 핵심 내용을 재배포하는 것이 됩니다. 가져오는 것은 형식과 체계입니다.
- 근거를 밝힐 때는 **문서명과 해당 절**을 적습니다 —
  `｢국가 망 보안체계 보안 가이드라인｣ 보안통제 항목 해설서 제1장` 형태.
  문서명은 꺾쇠에 넣습니다(`rules/06-notation.md`).
- 측정값을 인용할 때는 어디서 나온 수인지 밝힙니다 —
  "국내 사이버보안 가이드라인 20종에서 `~한다` 2,376회".
- 사용자가 참고할 원본 가이드라인을 가지고 있으면 읽어도 되지만, **찾은 문장을
  그대로 출력하지 말고 형식만** 가져오세요.
