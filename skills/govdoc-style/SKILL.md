# 공문서 문체 일관성

한국 정부·공공기관이 발행하는 간행물의 **문체 일관성**을 봅니다.
맞춤법·문법 오류(`되요` → `돼요`)는 다루지 않습니다 — 그건
`grammar-checker` 의 일입니다.

정답이 여러 개일 때 **문서 안에서 하나를 고르고 지키는 것**이 이 스킬의 목표입니다.

## 다른 스킬과의 경계

| 상황 | 쓸 것 |
|---|---|
| 맞춤법·띄어쓰기·조사 오류 | `grammar-checker` (korean-skills 원본) |
| AI가 쓴 듯한 문체를 사람 글처럼 | `humanizer` (korean-skills 원본) |
| 가이드라인 원고의 기계적 규칙 위반 | `guideline-lint` |
| 가이드라인을 새로 쓰기 | `guideline-writer` |
| 일반 문서(비즈니스·학술·기술·블로그)의 문체 일관성 | 업스트림 [korean-skills](https://github.com/DaleSeo/korean-skills) 의 `style-guide` |
| **공문서·간행물의 문체 일관성** | 이 스킬 |

## 먼저 장르를 정합니다

공문서라고 다 같은 문체가 아닙니다. 한국 정부 간행물 20종을 측정한 결과
네 장르가 뚜렷하게 갈립니다. **장르를 고른 뒤 그 열만 적용하세요.**

| 항목 | 법령형 지침 | 분야별 가이드라인 | 통제항목 체계 | 실무 안내서 |
|---|---|---|---|---|
| **종결어미** | `~하여야 한다` | `~해야 한다` | `~한다` | `~합니다` / `~하세요` |
| **번호 체계** | `제N장` / `제N조` / `①` / `1.` / `가.` | `제N장` / `제N절` / `N.` / `가.` | 표 중심 | `N.` / `N.N` |
| **등급 표기** | 한글만 (기밀·민감·공개) | `C/S/O` 약어 가능 | `C/S/O` 3칸 `●` | — |
| **금지 표현** | `~하여서는 아니 된다` | `~을 금지한다` | `~을 금지한다` | `~하지 마세요` |
| **경어체** | 금지 | 발간사·머리말만 | 금지 | 전체 통일 |
| **조문 인용** | `제4조제1항제1호마목` | 꺾쇠 + 조문 | 꺾쇠 + 조문 | 문서명만 |

장르가 모호하면 다음 신호로 추정하고, 그래도 모호하면 `AskUserQuestion` 으로 묻습니다.

- `제N조(제목)` 조문이 보이면 → 법령형 지침
- 통제항목 ID 와 등급 표가 중심이면 → 통제항목 체계
- 경어체가 비경어체보다 많으면 → 실무 안내서
- 분야(의료·전력·AI 등)와 `제N장/제N절` 이 있으면 → 분야별 가이드라인

## 검사 카테고리

우선순위 순입니다. 위쪽이 틀리면 아래쪽은 봐도 의미가 없습니다.

### 1. 강제력 종결어미 (최고)

공문서에서 종결어미는 문체가 아니라 **규범의 세기**입니다. 독자는 어미로
"반드시 해야 하는지"를 판단합니다.

| 등급 | 표현 |
|---|---|
| 의무 | `~해야 한다` / `~하여야 한다` |
| 금지 | `~을 금지한다` / `~하여서는 아니 된다` |
| 권고 | `~을 권고한다` / `~을 권장한다` / `~하는 것이 바람직하다` |
| 허용·선택 | `~할 수 있다` |
| 서술 | `~한다` |

점검할 것:

- **의무 표현의 두 변형이 섞였는가.** `~하여야 한다` 와 `~해야 한다` 를 함께
  쓰면 독자는 세기 차이가 있다고 읽습니다. 하나로 통일하세요.
  법령 인용문 안의 `~하여야 한다` 는 원문 그대로 둡니다.
- **법문을 요약해 옮길 때 문체가 섞이지 않았는가.** 법령 조문은 `~하여야 한다`를
  쓰므로, 조문을 표로 정리하다 보면 가이드라인 본문에 그 어미가 들어옵니다.
  **꺾쇠로 묶은 직접 인용이 아니라면 문서의 어미로 고쳐 쓰세요.** 직접 인용으로
  남길 문장은 인용부호 `“ ”` 로 묶어 인용임을 드러냅니다.
- **통제항목 설명문이 `~해야 한다` 로 끝나는가.** 이 장르에서 `~한다` 가
  이미 요구사항입니다. 전부 `~해야 한다` 로 쓰면 등급 구분이 사라집니다.
- **`~할 수 있다` 에 "무엇의 대안인지" 가 쓰여 있는가.** 대안 없이 쓰면
  독자는 해도 되고 안 해도 된다고 읽습니다.
- **권고가 통제항목의 10% 를 넘는가.** 조건을 명시할 수 있으면 권고보다
  조건부 의무가 낫습니다.

근거와 측정값: [`rules/05-normative-language.md`](../../rules/05-normative-language.md)

### 2. 경어체 (최고)

본체 간행물은 비경어체 평서형입니다. 코퍼스 20종에서 경어체 437회가
**실무 안내서·요약본 5종에만** 몰려 있습니다.

- 본체 문서에 `~습니다` / `~하세요` 가 있으면 고칩니다.
- **발간사·머리말만 경어체로 쓰고 본문에서 비경어체로 돌아오는 것은 허용**됩니다.
  코퍼스의 관행입니다.
- 실무 안내서는 거꾸로 — 문서 전체를 경어체로 통일하고 비경어체를 걷어냅니다.

### 3. 용어 통일 (높음)

같은 개념을 한 표현으로 씁니다. 측정된 선호는
[`rules/07-terminology.md`](../../rules/07-terminology.md) 에 있습니다.

핵심: 사용자(1,311) > 이용자(71) · 기관(3,197) > 조직(261) ·
정보시스템(834) > 정보 시스템(7) · 취약점(678) > 취약성(22) ·
침해사고(48) > 보안사고(16).

**법령·훈령이 정의한 용어는 코퍼스 선호보다 우선합니다.** 더 흔한 말로 바꾸면
법적 근거를 가리키지 못합니다. 법정 용어와 일반 용어가 겹쳐 보이면 통일하지
말고 **용어 정의에 범위 차이를 적으세요** — 예를 들어 `보안사고`는 ｢보안업무규정｣
제38조가 정한 개념이어서 `침해사고`로 바꿀 수 없습니다(`rules/07-terminology.md`).

**구별해서 써야 하는 세 용어**를 혼용하지 않도록 특히 주의하세요.

- **보안대책** — 위협에 대응하는 조치. 설명·근거를 포함한 서술 단위. 장·절 제목.
- **보안통제** — ID 가 붙은 요구사항 항목. 점검·이행 확인의 단위. 표.
- **보안 요구사항** — 시스템이 만족해야 하는 조건. 조달·설계 기준.

동사 구별: 문서·절차는 `수립`, 시스템·환경은 `구축` · 기준 대조는 `점검`,
적정성 판단은 `검토` · 범위 축소는 `제한`, 기술적 단절은 `차단`,
규범적 불허는 `금지` · 외부 규범은 `준수`, 자기 계획은 `이행`.

### 4. 법령 인용과 영문 병기 (높음)

[`rules/06-notation.md`](../../rules/06-notation.md) 가 근거입니다.

- 법령·지침·가이드라인 이름은 꺾쇠에. `｢ ｣`(315회)와 `「 」`(166회)를
  **섞지 말고** 하나로 — 정부 간행물의 관행은 `｢ ｣`.
- 조·항·호·목 사이는 띄우지 않습니다 — `제4조제1항제1호마목`.
- 영문 병기는 `한글(English)` 가 기본(1,010회). 약어 도입 형태
  (`한글(English Name, ABBR)` / `ABBR(Full Name)`) 중 하나로 통일.
- **첫 등장에만 병기**하고 이후에는 한글 또는 약어만.
- 약어가 10개를 넘으면 부록에 약어표.

### 5. 숫자·단위·날짜 (중간)

- 주기는 하한을 명시 — `연1회 이상`. `정기적으로` 만 쓰면 점검할 수 없습니다.
- 날짜는 `2026. 5. 1.`(마침표 뒤 한 칸) 또는 `2025년 4월`. 한 형태로 통일.
- 가운뎃점은 `·`(U+00B7). `ㆍ`(U+318D)는 검색·정렬이 깨집니다.
- `및` 은 마지막 항목 앞에만.

### 6. 목록·제목 형식 (중간)

- 1차 열거 기호는 문서에서 하나로 고정(`-` 또는 `•`). 열거 깊이는 2단까지.
- **목록 항목의 종결 형태를 통일**합니다 — 전부 명사구이거나 전부 완결 문장.
- 제목 레벨을 건너뛰지 않습니다. 실질 깊이는 3단(`제N장`/`제N절`/`N.`).
- `※` 는 문단·표 뒤 보충. 열거 목록 안에 섞지 않습니다.

### 7. 인용·강조·캡션 (낮음)

- 용어·값 강조는 `‘ ’`(343회), 원문 인용은 `“ ”`(210회).
- 캡션은 `[표 N]`(97회)과 `<표 N>`(10회) 중 하나로. 번호는 장 단위(`표 1-1`).
- 표·그림은 **번호로** 가리킵니다 — "아래 표"는 조판이 바뀌면 틀립니다.

세부 점검 항목은 [`references/checks.md`](references/checks.md) 에 있습니다.

## 작업 흐름

1. **텍스트를 받습니다.** 파일 경로면 Read, 여러 파일이면 문서 간 일관성까지 봅니다.
2. **장르를 정합니다.** 위 신호로 추정하고, 모호하면 묻습니다.
3. **기계적 검사를 먼저 돌립니다.** 가이드라인 원고라면
   `guideline-lint` 가 1·4·5·6·7 카테고리의 상당 부분을 자동으로 잡습니다.
   사람이 판단할 것만 남기고 시작하는 편이 빠릅니다.
4. **우선순위 순으로 봅니다.** 1·2가 틀렸으면 그것만 먼저 고치고 다시 봅니다.
   종결어미를 통일하는 과정에서 아래 카테고리의 문장이 바뀝니다.
5. **다수결은 기본값일 뿐입니다.** 장르가 정한 기준이 다수보다 우선합니다 —
   문서의 90%가 경어체여도 본체 가이드라인이면 비경어체로 바꿉니다.
6. **고친 결과를 보여줍니다.** 무엇을 왜 바꿨는지 카테고리와 근거를 함께.

## 명백한 패턴만 지적합니다

한두 번 어긋난 것은 패턴이 아닙니다. 다만 **1·2 카테고리는 예외** —
의무 표현과 경어체는 한 번만 어긋나도 규범의 세기를 흔들기 때문에 지적합니다.

사용자가 명시한 기관의 스타일 가이드나 발행처 양식이 있으면 **그것이
이 문서의 측정값보다 우선**합니다.

## 원본과 달라진 점

이 스킬은 [korean-skills](https://github.com/DaleSeo/korean-skills) 의
`style-guide`(MIT, Dale Seo)에서 **구조를 가져와 내용을 교체**한 파생본입니다.

가져온 것 — 카테고리를 우선순위로 나누는 방식, 장르별 매트릭스, 다수결 원칙,
참조 파일 분리, 작업 흐름의 골격.

바꾼 것:

- **문서 타입 4종을 교체했습니다.** 원본의 비즈니스/학술/기술/마케팅 대신
  법령형 지침 / 분야별 가이드라인 / 통제항목 체계 / 실무 안내서.
- **최우선 카테고리를 바꿨습니다.** 원본은 어조·격식이 1번이지만, 공문서에서는
  종결어미가 규범의 세기를 결정하므로 강제력 종결어미를 1번에 두었습니다.
- **기준의 출처를 바꿨습니다.** 원본은 일반 표준(정부·학술·실무)을 참조하지만,
  이 파생본의 모든 수치는 한국 사이버보안 가이드라인 20종(1,883쪽) 실측값입니다.
- **링크·참조 카테고리를 빼고** 법령 인용·영문 병기를 넣었습니다. 공문서에서
  더 자주 틀리는 쪽입니다.
- **한 곳에서는 측정값을 따르지 않습니다** — `정기적으로`는 코퍼스에서
  102회 쓰이지만 주기 하한을 적도록 권고합니다. 이유는
  `rules/06-notation.md` 의 숫자·기간 절에 있습니다.
