# 세부 점검 항목

`rules/` 에 없는 — 즉 측정이 아니라 공문서 작성 관례에서 오는 — 점검 항목만
모았습니다. 측정값에 근거한 규칙은 `rules/05~07` 을 직접 보세요.

중복을 피하려고 이렇게 나눴습니다. 같은 규칙을 두 곳에 적으면 둘이 어긋납니다.

---

## 목록 항목의 종결 형태

한 목록 안에서 항목들의 **문법적 형태를 통일**합니다. 코퍼스에서 가장 흔한
불일치입니다.

```
✕  - 접근 권한을 최소화한다
   - 계정 관리 자동화
   - 로그를 보관해야 한다

○  - 접근 권한 최소화
   - 계정 관리 자동화
   - 로그 보관

○  - 접근 권한을 최소화한다.
   - 계정 관리를 자동화한다.
   - 로그를 보관한다.
```

어느 쪽이든 되지만 섞지 않습니다. 선택 기준:

- **명사구** — 항목이 짧고 제목처럼 쓰일 때. 통제항목의 `소항목` 칸은 항상 명사구.
- **완결 문장** — 항목이 요구사항일 때. 통제항목의 `보안통제설명` 칸은 항상 완결 문장.

목록 도입부와 항목의 호응도 봅니다.

```
✕  다음과 같은 조치를 한다.
   - 접근 권한 최소화
   - 로그 보관한다

○  다음 조치를 적용한다.
   - 접근 권한 최소화
   - 로그 보관
```

---

## 제목 어구의 형태

제목은 **명사구**로 끝냅니다. 서술어를 붙이지 않습니다.

```
✕  ### 3. 위협을 관리한다
✕  ### 3. 위협 관리하기
○  ### 3. 위협 관리
```

같은 레벨의 제목끼리 형태를 맞춥니다.

```
✕  제1절 목적
   제2절 적용 범위는 어디까지인가
   제3절 관련 법령 및 지침

○  제1절 목적
   제2절 적용 범위
   제3절 관련 법령 및 지침
```

제목에 조사를 붙이지 않습니다 — `제2절 적용 범위` (`적용 범위는` 아님).

## 조사 호응

번호·약어 뒤의 조사는 **읽는 소리**를 따릅니다.

```
○  [표 3-1]과 같이            (표 삼의 일 '과')
○  N2SF-AC-1은               (일 '은')
○  SBOM을                    (에스비오엠 '을')
○  API를                     (에이피아이 '를')
○  CDS가                     (씨디에스 '가')
```

괄호 병기 뒤에 조사가 올 때는 **괄호 바깥**에 붙입니다.

```
✕  다중요소 인증(Multi-Factor Authentication)를 적용한다.
○  다중요소 인증(Multi-Factor Authentication)을 적용한다.
```

괄호 안의 영문이 아니라 **괄호 앞의 한글**에 호응시키는 것이 공문서 관례입니다.

## 피동·사동 남용

공문서에서 자주 과하게 쓰입니다. 통제항목은 **행위 주체가 분명한 능동**이 낫습니다.

```
△  계정은 자동으로 비활성화되어야 한다.
○  일정 기간 미사용된 계정은 자동으로 비활성화한다.

△  접근이 제한되어진다.          ← 이중 피동
○  접근을 제한한다.
```

다만 **주체를 밝힐 수 없거나 밝힐 필요가 없을 때**는 피동이 맞습니다.

```
○  모든 접근 요청은 로그로 기록된다.
○  승인되지 않은 포맷의 파일은 차단되거나 격리된다.
```

## 한 문장의 길이

통제항목 설명은 **한 문장**입니다. 조건이 둘 이상이면 문장을 늘이지 말고
강화 항목으로 쪼갭니다(`rules/03-control-ids.md`).

본문은 한 문장에 하나의 요구만 담습니다. `~하고, ~하며, ~하도록 한다` 가
세 번 이상 이어지면 끊으세요 — 독자가 어디까지가 의무인지 잃습니다.

```
△  관리자는 계정을 주기적으로 점검하고, 미사용 계정을 비활성화하며,
   권한 변경 이력을 기록하고, 분기마다 결과를 보고하도록 한다.

○  관리자는 계정을 연1회 이상 점검한다. 미사용 계정은 비활성화한다.
   권한 변경 이력을 기록하고 분기 1회 이상 결과를 보고한다.
```

## 괄호의 중첩

괄호 안에 괄호를 넣지 않습니다. 안쪽을 `[ ]` 로 바꾸거나 문장을 나눕니다.

```
✕  다중요소 인증(둘 이상의 요소(지식·소유·생체)를 조합)을 적용한다.
○  다중요소 인증을 적용한다. 인증요소는 지식·소유·생체 중 둘 이상을 조합한다.
```

## 예시 표기

```
○  (예: 이동통신사 인증 등)
○  * 다음의 인증요소 중 2가지 이상을 조합하여 활용
```

- 짧은 예시는 문장 안 `(예: … 등)`. `등` 으로 닫아 **열거가 닫힌 목록이 아님**을
  표시하는 것이 코퍼스의 관행입니다.
- 긴 예시는 요구사항 문장을 먼저 끝내고 `*` 로 분리합니다.
- `예를 들어` 로 시작하는 문장은 본문에, `(예: …)` 는 항목 안에 씁니다. 섞지 않습니다.

## 주체 표기

누가 하는지를 생략할 때와 밝힐 때를 구별합니다.

```
○  기관은 …한다.              ← 의무 주체가 기관일 때
○  …한다.                    ← 주체가 자명할 때 (통제항목 설명의 기본형)
△  우리 기관은 …한다.          ← '우리'를 쓰지 않습니다
△  담당자는 …한다.             ← 직책이 기관마다 달라 특정할 수 없으면 피합니다
```

통제항목 설명에서는 주체를 생략하는 것이 기본입니다. 주체가 **기관이 아닌
경우에만** 밝힙니다(`사용자는`, `개인은`, `외부 기관은`).

## 문서 간 일관성

여러 파일을 함께 검사할 때 추가로 보는 것:

- **용어가 문서마다 다르지 않은가.** 본문과 부록 체크리스트가 같은 통제를
  다른 말로 부르면 대응이 끊어집니다.
- **통제항목 ID 가 문서마다 어긋나지 않은가.** 본문에서 인용한 ID 가
  부록에 존재해야 합니다.
- **요약본이 전체본의 장 구성을 따르는가.** 요약본에서 장 구성을 바꾸면
  독자가 전체본의 어디를 봐야 하는지 알 수 없습니다.
- **같은 법령을 같은 이름으로 인용하는가.** `｢전자정부법｣` 과
  `｢전자정부법 시행령｣` 은 다른 문서입니다.
